# Evaluation

Two tracks, because the system has two components with different failure modes
and a single blended score would hide both.

## Track A — the scorer

`fraudsight train` → `artifacts/scorer_metrics.json`

Time-ordered split with a 14-day embargo. Three seeds, mean ± std. The test
split is touched **once**, to produce the final table — no threshold, no
hyperparameter and no feature decision is made against it.

Metrics: AUC-PR (primary), ROC-AUC (for comparability only), recall at fixed
FPR, Brier, expected calibration error, reliability curve, single-row latency
percentiles.

## Track B — the triage agent

`fraudsight eval --repeat 3 --floor` → `artifacts/eval_report.json`

### The dataset

`datasets/triage_holdout.jsonl` — 150 transactions from the **val** window,
inside the triage band, in three strata of 50:

- `confirmed_fraud` — label 1, score leans the same way
- `confirmed_legitimate` — label 0, score leans the same way
- `ambiguous` — **the label contradicts the direction the score leans**

The blueprint asks for "cases analysts disagreed on". This dataset records no
analyst disagreement, so ambiguity is defined mechanically and the definition is
published rather than implied. It is the stratum where a rule engine and an LLM
should diverge, and the one worth watching.

Only band-eligible transactions are used. Scoring the agent on transactions the
system would have auto-approved measures something it never does and inflates
agreement with easy cases.

### Metrics that are easy to fake, and how they are defined here

**Agreement.** Escalation is excluded from the denominator, not counted as
agreement — otherwise an agent that escalates everything scores 1.0. Reported
per stratum with a **macro** average, so the ambiguous third is not drowned by
the two easy ones. Always read alongside `decisive_rate`, which the gate also
checks.

**Groundedness.** Two independent measures, never averaged:

- *Numeric* — mechanical. Every number in an evidence detail must appear in the
  evidence bundle, at the precision it was stated. No judge involved.
- *Semantic* — the LLM judge, for claims stated without figures.

**Narrative quality.** 1–5 rubric, quadratic-weighted kappa when calibrated,
because being one point off is not the failure that being three points off is.

**Confidence calibration.** Stated confidence bucketed against measured
accuracy. Buckets with fewer than five decisive cases report `n` and no
accuracy — an accuracy computed on two cases is noise dressed as a finding.

**Variance.** `--repeat 3` reports mean ± std. A 2% improvement next to a 3%
spread is not an improvement.

### The floor

Every run also scores the rule-based provider on the same cases, tools and
index. The LLM's contribution is the **delta**, not the absolute score. Details
in [ADR 0007](../docs/adr/0007-deterministic-provider-as-floor.md).

## The judge, and why its numbers are unvalidated

`fraudsight calibrate` → `artifacts/judge_calibration.json`

An uncalibrated LLM judge is a random number generator with a confident tone.
The number that makes it trustworthy is Cohen's kappa against **human** labels.

**That has not been done.** `datasets/reference_labels.jsonl` is generated by a
deterministic rubric, so kappa is reported as `judge_vs_rules` with
`independent: false`. Because the judge and the reference share a rule set, a
high kappa there is self-agreement, not accuracy.

Consequence: **the eval gate does not gate on any judge-derived metric.** The
hallucination rate and narrative score are reported and explicitly unvalidated.
The mechanical metrics carry the gate.

To close it: [labelling_protocol.md](labelling_protocol.md), about 90 minutes.

## The gate

`fraudsight gate` — exits non-zero. What it checks:

| Check | Floor | Depends on the judge? |
|---|---|---|
| eval cases | ≥ 100 | no |
| repeats | ≥ 3 (published runs) | no |
| agreement (macro) | ≥ 0.85 | no |
| schema pass rate | ≥ 0.99 | no |
| numeric grounding | ≥ 0.98 | no |
| policy clean rate | ≥ 0.95 | no |
| decisive rate | ≥ 0.25 | no |
| judge hallucination rate | ≤ 0.02 | **yes — skipped until calibrated** |
| judge kappa | ≥ 0.60 | **yes — skipped until calibrated** |

It also refuses to pass on insufficient evidence: too few cases, or too few
repeats to have measured variance. A green gate on 12 cases is worse than a red
one.

## Red team

`fraudsight redteam` → `artifacts/redteam_report.json`

40 injection payloads through the **live pipeline**, injected into the fields an
attacker controls. Blocked means the recommendation did not move to `approve`
*and* nothing leaked. Results and the gaps: [docs/security.md](../docs/security.md).
